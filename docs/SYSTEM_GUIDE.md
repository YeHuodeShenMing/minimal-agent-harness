# 当前版本详细介绍

版本日期：2026-11-05（Asia/Shanghai）。本文描述实际源码与现有部署，架构题中的未来设计另见 architecture.md。

## 一、题目与实现对应

| 题目要求 | 实际实现 | 主要位置 |
|---|---|---|
| 从零实现 Agent 主流程 | 自研决策循环，不使用 LangGraph 等框架 | runtime.py |
| LLM 自主选择工具 | 注册名称、描述、参数 Schema，交给模型 function calling | tools.py、model.py |
| 至少三个工具，必须有 todo | calculator、todo、search、weather，共四个 | tools.py、online_tools.py |
| 接收输入、决策、执行、继续或结束 | 解析 final/tool_calls，按 call ID 回填结果 | runtime.py |
| 多 session 独立 | user_id + session_id 划分状态；Web 检查归属 | store.py、web.py |
| 纯对话与工具追问 | 近期消息进入上下文，工具读取精确业务状态 | runtime.py、todo |
| 长上下文压缩 | 真实模型摘要旧轮次，保留近期完整轮次 | runtime.py |
| 最大轮次、异常处理 | 默认最多 8 次主决策，协议修复、工具错误回填 | runtime.py、model.py |
| trace 与测试 | SQLite 事件表、网页执行面板、离线回归 | store.py、tests/ |

基础项之外，网页增加了匿名访问、实时状态轮询、自动标题与手动改名、Markdown、真实搜索/天气、自动推进的区域高亮教程。

## 二、请求如何走完

```text
浏览器 → HTTPS/Caddy → FastAPI → 后台线程池
                                  ↓
                         Runtime + SQLite 会话锁
                                  ↓
                 DeepSeek → 解析 tool_calls / final
                                  ↓
              Registry → 参数校验 → 工具执行 → 保存结果
                                  ↓
                       再请求模型，或结束任务
```

发送接口快速返回 accepted；浏览器约每 1.6 秒轮询当前会话。这是异步提交任务、轮询状态，不是 WebSocket 或 token 流式输出。两个后台线程用于任务执行；同一会话 busy 时拒绝重复提交。Uvicorn 当前部署为单 worker，不能直接增加 worker 数量并声称所有内存态限流仍然全局一致。

模型协议解析会校验响应类型、结束原因、工具调用 ID、参数字符串等。工具注册表校验项目使用的 JSON Schema 子集；不是完整 JSON Schema 标准实现。计算器采用 AST 白名单，不执行任意 Python 表达式。

## 三、用户身份与会话

没有账户注册、密码、用户资料表，也不需要邀请码。浏览器调用 `/api/visitor` 获得匿名身份：

```text
Cookie = 随机 user_id . 过期时间 . HMAC-SHA256 签名
```

线上 Cookie 使用 HttpOnly、Secure、SameSite=Lax；有效期 7 天。有有效 Cookie 时复用原身份。Cookie 保存身份凭证，不保存聊天全文；服务端验证签名和有效期。写请求还检查 CSRF Token 和 Origin，Host 受允许名单约束。

一个匿名身份可以创建多个会话。聊天、待办和摘要均按会话隔离；所有会话读取、改名、发消息接口检查其归属。两个标签页如果选择同一会话，访问的是同一状态；选择不同会话才隔离。

清除 Cookie、切换浏览器或身份过期后，旧数据库记录不会自动删除，但当前没有账号找回或跨设备续聊。CLI 的 `--user` 只是本机命名空间，不具备 Web 身份认证含义。

## 四、数据存在哪里

线上 SQLite 文件为 `/var/lib/minimal-agent/web.db`；本地默认 `data/web.db`。WAL 模式、事务提交、Unix 文件锁保护会话执行。

| 表 | 关键内容 |
|---|---|
| sessions | 联合主键 user_id/session_id；JSON state 包含 messages、summary、todos、active、steps 等 |
| events | 递增 seq、归属、事件类型、JSON payload、时间；保存模型决策事件、工具结果、错误、压缩归档 |
| web_sessions | 会话 ID、标题、所属用户、创建/更新时间、title_mode |
| web_usage | UTC 日期、访客 ID、任务次数 |

同一次工具执行产生的状态和 trace 在一个事务里写入。todo 存在 JSON state 中，不另建一套与消息状态脱节的数据库写入。已提交的 tool result 可用于恢复时识别已经执行的本地操作，避免再次添加同一待办。

这不等于外部服务 exactly-once：未来若添加支付、邮件等外部副作用工具，仍需幂等键、状态查询或补偿。

浏览器 localStorage 只保存当前会话选择和导览标志；模型密钥在服务器 `.env`，Cookie 签名密钥在线上服务环境文件。数据库和这些配置不应加入公开仓库。

## 五、上下文与 memory 的取舍

模型输入依次包含：系统规则和当前 UTC 时间、标为不可信资料的历史摘要、近期消息。工具 schema 随请求提供；工具返回值通过对应 call ID 回填。

三类状态各有用途：

- 原始事件：保留追溯证据和压缩移出的原文。
- 结构化 todos：保留精确 ID、内容和完成状态，不靠摘要猜测。
- 工作上下文：摘要加近期完整轮次，供模型理解目标和追问指代。

预算按 UTF-8 字节估算，默认 48,000 bytes，超过预算才压缩。摘要调用是额外真实模型调用；8 步限制不等于整个任务最多 8 个 HTTP 请求。摘要失败或超长不会直接删除原始历史。没有向量检索、自动原文回查或跨会话 memory。

不请求、不展示、不落库私有思维链。网页展示的是工具选择、参数、结果、耗时和异常，而不是模型隐藏推理。

## 六、真实工具与前端

Open-Meteo 根据城市匹配经纬度，提供当前天气估算和未来 7 天预报，返回匹配地区、时区、单位和来源；Tavily 固定使用 basic 搜索，返回最多 5 条标题/摘要/URL。请求有超时和响应体大小限制，HTTP 错误不把密钥暴露给模型或浏览器。网页结果属于不可信数据，不能覆盖系统指令。

原生 JS 负责会话列表、聊天轮询、工具面板和导览。助手文本用 Marked 转换并经 DOMPurify 白名单清理；用户文本使用 textContent。前端依赖文件已随包附带，不依赖 CDN。

首条消息先提供内容短标题，首轮回复完成后另调用模型概括；失败保留短标题。手动改名标记 manual，后台自动标题更新使用条件写入，防止覆盖手动修改。

导览以真实操作和任务完成事件推进：提交计算/待办 → 查看工具详情 → 新会话查待办 → 回原会话完成待办 → 查看历史摘要。消息不会仅因点开教程自动发送。任务未完成时保留步骤供重试；可手动跳过。短对话没有压缩摘要是正常状态，教程不注入虚假的压缩结果。

## 七、适合说明的工程亮点与边界

值得讲清楚的是状态转换、协议配对、原子提交和压缩取舍，而不只是页面美观。当前已有测试涵盖故障与恢复、隔离、超预算、标题竞态、联网工具错误处理等。测试数量本身不代表生产稳定性或压缩语义无损。

公开演示仍有资源限制：默认每访客每天 20 次、全站每天 80 次任务，最多 20 个会话，每会话最多 100 条待办。游客可以换 Cookie，因此用户级额度不是可靠身份限额；全站额度才是更直接的任务总量约束。标题、摘要、工具请求的次数与费用不能简单等同于任务数。

下一步合理方向是账号与找回、数据库与任务队列扩展、更准确预算和总任务期限、原文按需回查，而不是立即增加复杂框架。
